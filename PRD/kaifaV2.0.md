# 第一部分　阅读须知（开卷必读，10分钟）

## 1\.1 这本手册怎么用

你是本项目的产品经理，兼项目唯一驱动人。这本手册把《找个人帮忙》小程序从环境部署、初始化、开发、测试到正式部署的全过程，拆成了若干个可独立执行的小步骤。每个步骤都包含五个要素：本步目标、你的手动操作、投喂 TRAE 的提示词、完成标准、常见坑。你只需要严格按顺序执行，不需要理解代码本身。

### 表 1\-1　你手里的三个工具与分工

|工具|扮演的角色|你在里面做什么|
|---|---|---|
|TRAE（Trae Code CN）|程序员。负责读懂提示词、生成和修改全部代码|开对话、粘贴提示词、让它执行；报错时把报错贴回给它|
|微信开发者工具|调试台＋模拟器。负责运行、预览、调试小程序和云开发后台|导入项目、点【编译】预览、查看云开发控制台（数据库/云函数/日志）|
|微信公众平台（mp\.weixin\.qq\.com）|管理后台。账号、成员、隐私声明、类目、提交审核都在这里|获取 AppID、配置成员与隐私保护指引、上传审核材料、发布上线|

### 五条执行纪律（务必遵守）：

- 一次只发一个提示词。发出去、等 TRAE 生成完毕、按完成标准验证通过后，再发下一个。绝对不要把多个提示词一次性全部粘贴给 TRAE。

- 每个提示词都要从【提示词开始标记】到【提示词结束】完整复制，一个字都不要漏。

- 先发阶段 1 的全局规则（Step 0），再做其他一切。它决定了 TRAE 对本项目所有合规红线的记忆。

- 报错不慌。把报错原文完整复制，套用本章 1\.4 的报错模板发回给 TRAE，一般两三轮就能修复。

- 每天结束时保存进度。代码用 Git 提交（阶段 0 有一步专门教你），文档与账号信息记录在本手册第 2\.6 节的《项目信息登记表》里。

## 1\.3 本期架构决策与必须书面知悉的风险

PRD 第 14、15 章描述的是面向百万级用户的完整目标架构（微服务、MySQL、Redis、ES、RocketMQ、K8s）。作为架构师，我在 Sprint 0 做出如下裁剪决策：MVP 阶段全部跑在微信云开发（CloudBase Serverless）上，等日活过万再按 PRD 的三阶段扩容路径迁移。这一决策让你一个人也能完成开发与运维，且月成本可控制在 20～50 元量级。

### 表 1\-4　PRD 目标架构 与 MVP 落地架构对照

|PRD 目标架构|MVP 落地方案|迁移时机|
|---|---|---|
|微信原生小程序（C 端）|一致：微信原生小程序 JS 版|不变|
|Java SpringBoot 微服务 \+ API 网关|微信云开发云函数（Node\.js）按业务域拆分|DAU 过万或复杂规则爆炸时|
|MySQL 8\.0（12 张主表）|云开发文档型数据库（集合与 PRD 主表同名对应，字段尽量同名）|同上；导出 JSON/CSV 可搬|
|微信支付服务商分账|模拟支付（is\_mock 标记），资金零过手|完成主体升级并开通商户号后|
|腾讯云 IM|云数据库实时推送（watch）单聊|并发上来后按 PRD 第 11\.6 节迁移方案执行|
|人脸核验 / AI 心理预警 / TRTC|占位：入口与文案保留，逻辑返回「功能升级中」|V16 及以后，需企业资质|
|Redis/ES/RocketMQ/K8s|不使用；用数据库索引与云函数定时器满足 MVP|成熟期|
