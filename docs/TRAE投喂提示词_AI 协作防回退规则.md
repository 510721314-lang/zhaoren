# 微信小程序 · AI 协作防回退规则

核心目标：杜绝"改一个 bug，坏三个已调好的功能"。

## 0. 开工前必读（不可跳过）
动手改代码前必须先读：
1. 本文件
2. docs/FUNCTION-REGISTRY.md —— 已验证功能清单与人工验收步骤
3. docs/CHANGELOG.md —— 近期变更与回归结论
未读取就改代码视为违规。文件不存在时先提醒我创建。

## 1. 第一原则：最小改动
- 除非我明确要求，禁止对已能正常运行的代码做：重构、性能优化、统一风格、格式化、重命名、调整目录、更换写法、补注释、删除"看起来没用"的代码。
- 禁止整文件重写，禁止"重新生成整个页面"。只做增量修改。
- 单次改动默认上限：3 个文件、30 行。超出先停下来问我。
- 我让你改 A，不能顺手改 B。禁止"顺便优化""顺手修一下"。
- 看不懂某段代码用途时先问，禁止猜测后删除或改写。
- 改 WXSS 时只改目标选择器，禁止重写整个样式块、禁止改全局 app.wxss 除非点名。

## 2. 已验证代码神圣不可侵犯
- 带 // @VERIFIED 标记的函数/组件/文件表示已通过真机验证：
  - 禁止修改其内部逻辑，除非本次需求中点名要求；
  - 确需修改时，先说明"为什么必须改" + 给出向后兼容方案（旧调用方、旧字段名仍可用），等我书面批准。
- 我告诉你某功能调通后，主动提醒我加标记：// @VERIFIED 日期 已真机验证：xxx

## 3. 先说后做（我批准前不得写入文件）
动手前只输出方案，必须包含：
1. 根因定位：精确到 文件路径:行号，说明为什么错。禁止"大概是""可能是"的猜测式修改。
2. 改动清单：每个文件改哪一处，各一句话。
3. 影响面评估：对照 FUNCTION-REGISTRY 逐条比对，列出可能被波及的既有功能。
4. 风险等级：高/中/低 + 判断依据。
5. 触发以下任一条件必须停下来问我：
   - 涉及 app.json / app.js / app.wxss / project.config.json / sitemap.json / ext.json
   - 涉及公共组件、utils/、request 封装、登录态 / token 逻辑、全局状态
   - 涉及接口字段、云函数、数据库集合、缓存 key
   - 涉及基础库版本、插件、分包结构、渲染引擎、npm 依赖
   - 涉及登录、授权、支付、订阅消息、上传下载、定位等能力链路

## 4. 小程序高危改动区（碰之前必须说清后果）
| 高危项 | AI 最常犯的错误 | 强制要求 |
|---|---|---|
| app.json | 新增页面忘记注册、改动 tabBar 顺序、误删已注册路径 | 新增页面必须同步注册；禁止改动已有 tabBar 项与页面路径 |
| project.config.json | 误改 appid、miniprogramRoot、npm 打包配置 | 禁止擅自改动；确需改必须说明并单独提交 |
| project.private.config.json | 覆盖个人编译条件、勾掉"不校验合法域名" | 一律禁止修改 |
| 基础库版本 | 擅自调高导致低版本用户白屏 | 禁止改动，除非我要求 |
| 渲染引擎 | 误开 Skyline，导致 WXSS 大面积失效 | 禁止改动 renderer / rendererOptions |
| setData | 整对象覆盖、单次数据量过大、后台页调用 | 只传变化字段或用路径写法；长列表禁止整体替换 |
| 组件 properties / data | 字段改名后 WXML 引用失效 | 改名前列全部引用点，经我确认后再改 |
| 样式隔离 | 组件样式不生效就改全局 | 先说明 styleIsolation 方案，禁止直接搬进 app.wxss |
| 云函数 | 改了本地代码不部署就说"已修复" | 必须提示我"需右键上传并部署" |
| npm 包 | 装完没构建就说能用 | 必须提示我"需执行构建 npm" |

## 5. 小程序专项红线
- 页面栈：navigateTo 最多 10 层；switchTab 不能带参数；redirectTo 会销毁当前页。改动跳转逻辑必须列出受影响的返回路径。
- 生命周期：onLoad 只执行一次、onShow 每次进入都执行、tabBar 页不会触发 onUnload。改数据初始化位置时，必须说明为什么放在对应生命周期。
- 登录时序：wx.login → 自定义登录态 → 业务请求 的顺序不得打乱；禁止在 app.js 内加"顺手"的并发改造。
- 隐私协议：涉及 getUserProfile / getPhoneNumber / 相册 / 定位等，必须确认已在 app.json 的 __usePrivacyCheck__ 与小程序后台配置，否则接口静默失败。
- 合法域名：新增接口域名必须提醒我去后台配置 request 合法域名，否则真机必失败。
- 体积限制：主包 2MB、单分包 2MB、总包 20MB。新增依赖必须评估体积影响。
- 能力链路：登录、支付、授权、订阅消息、上传下载、蓝牙、定位——任何相关改动一律列为回归清单第 1 条，并标注"必须真机验证"。
- UI 改动：滚动、键盘弹起、安全区、字体、图片、rpx 适配——一律标注"需 iOS 与 Android 真机各验一遍"。

## 6. 改完必交回归验证清单（缺此项 = 任务未完成）
任何改动后必须输出：
1. 变更清单：文件 + 改了什么 + 为什么改。
2. 回归验证清单（表格）：序号｜需回归的既有功能｜验证步骤（开发者工具/真机）｜预期结果｜谁验。
3. 区分两类验证：你可在开发者工具自证的（语法、编译、Console 无报错、Network 请求字段）你自己过一遍并说明结果；必须由我人工/真机验证的明确列出，不要含糊带过。
4. 涉及云函数、npm 构建、后台配置时，在清单里单列"需我手动操作"项。
5. 禁止以"已完成""应该没问题""现在可以了"收尾而不给验证步骤。

## 7. Bug 修复纪律
- 一次只验证一个假设，禁止把多套方案同时塞进去的"扫射式修改"。
- 连续两次尝试未解决，立即停下：说明现状 + 已排除的可能 + 需要我提供什么（报错原文、开发者工具 Console 日志、复现步骤、真机表现截图）。禁止继续盲改。
- 治本不治标，禁止以下"假修复"：用 try/catch 吞掉异常；用 setTimeout / 加大延时掩盖时序问题；注释掉代码、加 return 跳过逻辑；把 wx:if 改成 hidden 绕过渲染报错；反复 setData 空对象"试试看"。
- 需要报错信息或真机表现时先向我要，禁止凭想象编造。

## 8. 回答格式（固定，全程中文）
【结论】→【根因分析（含 文件:行号）】→【改动计划/变更清单】→【风险评估】→【回归验证清单】→【需要你确认或手动操作的事项】
代码关键处加中文注释，但不得改动与本次需求无关的既有注释。
