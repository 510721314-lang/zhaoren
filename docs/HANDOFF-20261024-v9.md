### C-4.x 新增工具链（v9 无）

| 编号 | 工具链 | 内容 |
|---|---|---|
| C-4.32 | **nosql execute 绕过 PowerShell 引号铁律（v8 C-4.27 强化）** | v8 写了 `node spawnSync tcbBin`，本轮实测更通用：**在 `.cjs` 脚本里 `spawnSync(cliFullPath, argsArray, {shell:false})`**，args 数组直接放 JSON 字符串（不是拼 shell 命令）。cliFullPath = `C:\Users\Administrator\AppData\Roaming\npm\cloudbase.cmd`。**PowerShell 引号吞 stdin 必炸，shell:false + args array 是唯一正确姿势** |
| C-4.33 | **nosql dump 返回 NDJSON** | 导出文件是 NDJSON（每行一个 JSON 对象），直接 `JSON.parse(content)` 会炸 `Unexpected non-whitespace character after JSON at position X`。必须按 `\n` split 后每行 parse：`lines.map(l => JSON.parse(l))` |
| C-4.34 | **wx-server-sdk 本地装后无凭据** | `cloud.init()` 后 `db.collection().get()` 抛 `missing secretId or secretKey`；**CLI 自带凭据**（已登录）可用 dump/nosql execute 绕开，不需要 tcb login 再调 sdk |
| C-4.35 | **miniapp-mcp 入口文件坑** | 包用 ESM（`"type": "module"`），`dist/index.js` 是**纯导出模块** `export { startServer }`，直接 `node dist/index.js` → 什么都不做 → 立即 exit → Trae 报 `Connection closed`。**真正 bin 入口是 `dist/cli.js`**（内部调 `startServer()` 启动 stdio） |
| C-4.36 | **Trae MCP 自动加 mcp_ 前缀** | GUI 里注册 `"weapp-test"` → `run_mcp` 实际可用名 = `"mcp_weapp-test"`。**server_name 必须写 mcp_weapp-test 而不是 weapp-test** |
| C-4.37 | **Windows miniprogram_launch 启动失败 → 两步走** | `miniprogram_launch({cliPath, projectPath})` 在 Windows 下内部调 cli.bat 的路径解析有坑（EINVAL）。**替代方案**：①手动 `cloudbase.cmd db nosql dump admin_config` 绕过；②MCP 侧：先 `cli.bat auto --project ... --auto-port 9420` 启动 → 再 `miniprogram_connect({port: 9420})` 两步走 |
| C-4.38 | **miniprogram_screenshot filename 不能含路径分隔符** | `"home.png"` ✅，`"C:\zhaoren\home.png"` ❌（报 `Filename must not contain path separators`）。截图文件存 server 默认目录（`.mcp-artifacts/session-xxx/`） |
| C-4.39 | **Trae .trae/mcp.json 是受限文件** | Agent 不能 Write/Edit 写入 `.trae/mcp.json`。**唯一办法**：用户在 GUI（设置 → MCP → 手动添加）里粘贴 JSON 配置 |
| C-4.40 | **Trae MCP command 字段不能含空格** | `"node"` ✅，`"C:\Program Files\nodejs\node.exe"` ❌（空格导致命令解析错误） |
| C-4.41 | **cloudbase CLI --envId 已废弃** | 3.8.5 版本用 `--env-id`（带连字符），旧 `--envId` 打 warning 但还能跑 |
