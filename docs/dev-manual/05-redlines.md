# Ch5 · 硬约束与红线

> 事实来源：项目既有硬约束（`project_memory` Hard Constraints）。这些是**不可随意触碰**的规则；改动需先经用户明确同意。

## 5.1 安全与鉴权（最高优先级）

- **fail-closed 原则**：AI、云调用、权限声明等失败时一律降级/拒绝，绝不放行主流程。
- 生产环境 `mock_openid` **全部失效**，身份一律取真实 `OPENID`；dev 旁路需携带未来时间戳 `dev_until` 才生效，过期自动回退 prod。
- 环境判定依赖 `admin_config.global.env` 云端运行值，**读取失败按 prod 兜底**（不隐式放开 mock）。切 dev 后有 4 小时自动回 prod 兜底。
- 网关鉴权优先级：`X-Admin-Token`（`admin_web_sessions` 12h）> `admin_login` 免 key > `X-Admin-Key` 兜底。
- `admin_login` 失败必须写入 P1 事件 `admin_login_fail` 到 `platform_event`（供 errorScan 巡检），避免匿名爆破无观测。
- 密钥轮换须提供合规生成脚本 + 演练脚本；`phone_hash` 随密钥同步重算。
- **手册不写凭据明文**：环境 ID / AppID / AppSecret / admin key / 加密密钥一律只记「存放位置与读取机制」。

## 5.2 资金安全

- 退款金额上限 = 订单总额 − 已成功退款合计（**不含打赏**）；超额、零额、非整数一律拦截。
- 退款失败必须**自动补偿回滚**订单状态，避免状态不一致；退款成功后向双方推站内通知（含金额，可跳详情）。
- **部分退款仅冲减结算基数**，**不进入全额退款终态 S7**。
- 结算基数支持双方各确认一次；部分完成确认后自动生成剩余金额退款工单。
- 分段结算口径：完成比例 ≥50% 按比例结算，<50% 按 10-20% 到场补偿（可配置）。
- 生产环境打赏功能（`tip_enabled`）**自动关闭**。
- 资金字段（`paid_fen`/`refunded_fen`/`settle_state`）双写须与状态机正交位同步落地。

## 5.3 订单状态机与履约域

- 状态迁移采用**表驱动白名单**，所有状态变更经 `casStatus` **乐观锁**并发保护。
- 订单状态机重构采用**双写过渡**：先同时写旧状态字段与新正交位字段，存量迁移完成后再全仓切换读方，避免读写空窗。
- 存量迁移**前必须全量备份**，分批 `limit`+`skip` 执行，迁移后抽样验证一致性。
- **所有等待类状态必须配置超时守夜人兜底**，避免订单永久滞留。
- 争议裁决完成后回退状态需**保留原状态上下文**（已有评价的争议回退应返回 S8 而非固定 S5）。
- 履约状态语义必须保证 **admin 端与小程序端完全一致**，避免两端标签语义相反。
- 冻结位（`frozen=true`）期间禁止 start/modify/complete/evaluate，且**隐藏「发起投诉」按钮**。
- 3B 爽约申诉可提交条件：订单状态为 **S2 或 S3.5**，且落在「约定开始时间 ≤ now ≤ 约定开始时间 + 48 小时（可配）」窗口内；未到开始时间返回 `no_show_not_started`。
- 爽约申诉链路：提交（需截图举证，≥10 字）→ 对方举证（48h 窗口）→ 管理端裁定（成立：扣 20 分/次，满 3 次停用 7 天）；申诉人裁定前可随时撤回。
- **S2 协商取消链**：不新增独立状态，用 `cancel_request` 挂起字段实现（含发起方/原因/预计算金额/2h 过期）。金额冻结以**发起时点**为准；超时转裁决按裁决时点梯度重核。
  - 角色不对称梯度退款：用户取消按距开始时间分全额/80%/50% 三档；耍伴取消任意时间全额 + 平台赔付 20% 并扣 20 信用分。
  - 挂起期间冻结 start/modify；与爽约申诉并存时**申诉优先**自动撤回取消申请。
  - 转裁决为**专用双出口**：同意取消按裁决时点梯度退款 → S7；驳回清挂起回 S2。
  - 同方被拒后不可重发，每单双方合计发起上限 2 次，满额仅剩裁决入口。
- **履约催办三段式**：到点提醒耍伴 → 超时 1h 用户收通知 + 催办入口亮起 → 超时 4h 自动引导爽约申诉。每单限手动触发 **2 次**，满额置灰。
- 加时申请超时自动拒绝：S3 且存在 `pending_extend` 时，以 `expire_at` 或 `created_at+modifyConfirmH` 判定超时，写 `timeout_extend_auto_reject` 时间线 + 发 `extend_reject` 通知，用 `pending_extend_token` 乐观锁防竞态。
- 订单相关事件（投诉/爽约/改期等）必须在订单详情页以**统一时间线**倒序展示，操作人角色可读化，**不暴露原始 openid**。
- 纠纷/申诉历史汇总合并四类数据源：状态流水 + 投诉记录 + 爽约申诉 + 支付/退款流水。
- `order-timer` 所有扫描统一使用**分页循环**，避免单页 `limit` 导致积压超 50 笔的部分单据永不被处理，单轮硬上限 500 笔。

## 5.4 隐私、合规与展示

- 手机号/座机**脱敏存储**：`138****5678` / `028-****8888`。
- 订单付款后，接单方可看需求发布者联系电话；代发订单另显示被代发人电话，均脱敏 + 拨打占位提示。
- 所有需求发布必须留**已验证**联系手机号；付款后接单者通过系统虚拟号联系发布者，履约结束 3h 后（可配）虚拟号失效。
- **地图位置共享双向对称**：需开启 `allow_map_share` 且定位在 15 分钟内有效对方才能在地图看到你；`report_map_gps` 仅在 `allow_map_share=true` 时写坐标，关闭时**自动清除**已上报坐标。
- 地图 marker 角色区分：耍伴绿色（`marker.png`），发布者蓝色（`marker-user.png`），按 `is_partner` 判断。
- **耍伴展示资料只读 `profile_audited_snapshot`**，未过审内容一律不上线（fail-closed 双缓冲）。
- 资质/荣誉**审核双向进入人工**，不含 auto 通过；标题长度 ≤20，图片 ≤6 张，单张 ≤3M。
- 资质/荣誉添加入口**恒显示**，满额时 toast 提示上限（不得隐藏按钮）。
- 资料维护与入驻审核解耦：`update_partner_profile` 门槛为 `status !== 'rejected'`（`pending_review` 可维护）；驳回时写 `profile_submit_at: 0` 清除 30min 限频，允许立即重提。
- 每栏目独立提交/审核：通过的栏目并入快照并清除其 pending，驳回的仅清 pending 保留 reason，全部处理完才解除整份 `pending` 锁。

## 5.5 需求发布与配置一致性

- 需求发布时 `status≠cancelled` 的需求参与**时间窗冲突**判定。
- 代发需求：被代发人联系方式必填，校验手机（11 位，`1[3-9]` 开头）与座机（区号+连字符+7-8 位）；与被代发人关系从预设列表选择，「其他」需 20 字内说明。
- 场景/子场景白名单从 `admin_config.scene_list` **动态读取**；隐藏仅控制前端入口展示，存量已发布需求仍正常可见。
- 隐藏过滤逻辑**统一在 `home-action` 的 `scene_groups` 出口**执行；`scene_list` 单场景分页、`nearby` 白名单、`demand-publish` 白名单**不做过滤**。
- 前端三处兜底场景列表需防泄漏：全部子场景隐藏时不再回落硬编码；`SCENES` 仅在云端列表为空时才用兜底；升级 swr key 版本清旧缓存。
- 商家首页场景宫格默认展示 5 个常用场景，其余入「更多场景」就地展开（不跳页）；搜索不受折叠限制。
- 活动卡片方形 1:1；标题/副标题空则不渲染正文区；后台提交与云端存储统一 trim。
- 上传封面强制校验 1:1，非正方形返回 `up_not_square`。
- `admin_config.scene_list` 缓存 5 分钟、`scene_groups` 缓存 60 秒——运营改显隐后最长约 5 分钟生效，须提前告知。

## 5.6 通知与巡检

- 需求发布成功后必须立即推送发布者站内通知，并向符合条件耍伴推抢单通知，全程 fail-closed。
- 客服会话唯一索引约束：`im_conversation.uk_order_id` 唯一，客服场景固定 `order_id: ''`，全局仅一条客服会话。
- 巡检（errorScan）仅对真实用户的 P0/safety_sos 事件告警，豁免 `admin_probe`（无身份机器调用）与 `order-timer` 自身 `s4_stale_escalate` 兜底事件。
- 订阅消息：**云调用（cloud.openapi）仅在小程序端触发的云函数中经微信自动鉴权成功**；定时器/HTTP 网关/控制台/CLI 触发必报 `-501001`。HTTPS 订阅走 opt-in（配置了 `sub_msg_https` 才启用），`defaultPostJson` 设 8s 超时；pusher 在函数级创建 + `getAccessToken` in-flight 去重。
- 订阅模板选型红线：仅选 `thing`（文本）+ `time`（时间）字段，避开 `phrase`/`amount`/`character_string`/`name`；提审前 `miniprogram_state` 设 `trial`。
- 发送结果统一写 `demand.sub_msg_send_logs`（含通道标注），是无日志通道时验证订阅/云调用的有效手段。

## 5.7 交付与提审策略

- 已验收基线内容的修改**必须先经用户同意**。
- 提审策略（2026-10-10 拍板）：履约域各批次全部纳入**提审前**完成，对提审时间无限制，交付相对完善产品；但**范围不开放**——提审准入以既定验收标准达成（三审计零 P0 + 每 Wave DoD + 真机全生命周期回归）为准，新增需求走常规流程单独评审。
- 提审前必须完成：所有云调用权限声明补齐、静默降级日志升级（确保 openapi 失败在生产可观测，无无痕静默失败）。
- 提审演示/截图期间可临时切 dev，**完成后立即切回 prod**。
- 新开任务必须进行工作目录验证并经用户确认后才能动工。

## 5.8 已知留存负债（提审前不修，需登记）

- `order-timer` 分页 `skip` 漂移：仅在并发写者活跃且单段积压 >50 时触发，影响为延迟一轮，提审前不修，待单段 backlog 告警或日单量 >500 再评估游标分页。
- 争议单超期升级（`dispute_escalate_d=30`）当前为**预留人工处理**，不验证自动升级。
