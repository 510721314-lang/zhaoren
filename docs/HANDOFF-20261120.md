- **E-6.50【verify:offline 与 ab_equivalence 并行会竞态假失败，必须串行】** `ab_equivalence.js` 运行时在各云函数目录动态创建/删除 `__baseline_tmp_<pid>_<ts>.js` 临时基线文件；若与 `verify:offline`（首步 `check-syntax.js` 扫描 `cloudfunctions/**/*.js`）并行，临时文件会被扫到但 require 时已被删除 → 报 `[SYNTAX FAIL] ... __baseline_tmp_*.js` + `Cannot find module` + `SYNTAX CHECK FAILED: N file(s)`，`verify:offline` exit 1。**本会话实证**：并行跑失败 9 文件，磁盘 `Get-ChildItem __baseline_tmp_*` 实测零残留，单独串行重跑 `verify:offline` 立即 EXIT=0。**结论**：①门禁命令不得与 ab_equivalence 并行；②判 verify 失败前先 `Get-ChildItem -Recurse __baseline_tmp_*` 查是否竞态残留，零残留 + 报错指向 `__baseline_tmp_` = 假失败，单独重跑即可，禁止据此改业务代码或刷新基线。 **2026-11-26 已根治**：6 个扫描门禁（check-sub-msg-consistency / check-rule-refs / check-prd-drift / check-require-scope / check-silent-catch / check-shared-sync）统一加 `__baseline_tmp_` 前缀豁免 + check-tech-debt-header 中 ab_equivalence spawn 失败重试 1 次；并发复现实证（9 个临时文件存在期间 6 门禁全 PASS、ab 退出残留 0、A/B 473 等价）。本条诊断法保留为历史防复发参考。
- **E-6.51【规则配额 inject 余量仅 361B，新增规则前必须先淘汰/下沉】** 2026-11-20 实测 `check-rules-size` inject 17047B/17408B（目标位 17408B），余量 361B，已触发 `[L0-HEADROOM] inject 距目标位仅 361B（<512B），新增前须先淘汰/下沉旧条`。**硬顶 30720B** 是绝对上限，但脚本以 17408B 为目标位告警（留安全余量）。**结论**：①任何新增 `project-rules-core.md` / `project_rules-20261013.md` 规则条款前，先评估能否改写为更短表述、或下沉到 `.trae/documents/` 归档 / 技能 SKILL.md，再决定是否新增；②禁止为一次性会话结论加常驻规则（落 session-log 即可）；③加完必须跑 `node scripts/check-rules-size.js` 确认 EXIT=0 且无新告警，否则回退。
- **E-6.52【Vite 懒加载产物线上验证法 + PS5 中文编码假 False】** 验证线上 admin-web 常量（STATUS_MAP 等）时主 chunk 不含——先拉主 chunk 正则提取懒加载 chunk 名（`format-*.js`），再下载该 chunk 验证。**坑**：PS5 `Invoke-WebRequest` 对无 charset 的 JS 响应按错误编码解码，中文 `Contains` 全部返回 False 假象（本会话两次误判）；必须 `curl.exe -o <file>` + `[IO.File]::ReadAllText($f, [Text.Encoding]::UTF8)`。实证：线上 `format-67u7ASjr.js`（1327B）STATUS_MAP 16 键逐字命中（REGISTRY #184 批2）。
