## §6 经验教训（清点项 E-6.x）

> 经验载体链：**E-6.1~E-6.16 见 HANDOFF-20261110 §6；E-6.17~E-6.19 见 20261111；E-6.20~E-6.25 见 20261112；E-6.26~E-6.28 见 20261113；E-6.29~E-6.30 见 20261114；E-6.31~E-6.36 见 20261115 §6；E-6.37~E-6.39 见 HANDOFF-20261117 §6；E-6.40~E-6.45 见 HANDOFF-20261118 §6**，全部继承有效，此处不重抄；本节只补 2026-11-19 新增四条。

- **E-6.46【PS5 `Set-Content/Out-File -Encoding UTF8` 会叠加 BOM】** 每次写入都强制前置 `EF BB BF` 且**不剥除文件已有前导 BOM**，同一文件被多次此类保存会叠加多个 BOM（本会话 `register-backup-tasks.ps1` 实证出现 4 个 BOM，首行注释前叠了 3 个）。还原用 `git checkout <file>`；如需写无 BOM UTF-8，用 `[System.IO.File]::WriteAllText($path,$text,[System.Text.UTF8Encoding]::new($false))`。**改 .ps1 后务必 `git diff` 核首行无 BOM 叠加**。
- **E-6.47【push 成功判据必须 `ls-remote` 实证复核】** `git push` exit code 0 或空输出 ≠ 成功（曾遇 `Everything up-to-date` 误导 + 代理抖动假成功）。必须 `git -c http.proxy= -c https.proxy= ls-remote origin master` 实证远程 SHA == 本地 HEAD 才算数。**注意 `ls-remote` 也要带 `-c http.proxy= -c https.proxy=`**，否则走失效代理报 `Failed to connect 127.0.0.1` 假失败（本会话实证）。
- **E-6.48【顽固目录删除：先清只读 + robocopy 空镜像法】** `.NET [System.IO.Directory]::Delete` 递归删除遇只读文件抛「对路径…的访问被拒绝」。正确步骤：① `Get-ChildItem -Recurse -Force | % { $_.Attributes='Normal' }` 清只读；② 仍失败用 `robocopy <empty_dir> <target> /MIR /NFL /NDL /NJH /NJS /R:1 /W:1` 清空（rc≤7 算成功）再 `Remove-Item`。大目录 robocopy 可能卡死，须监控进程（大小不动且无 robocopy 进程 = 卡死，交用户手工删）。
- **E-6.49【milestone 前端无确认入口，全靠 timer 自动确认】** `order-action` 有 `milestone_confirm` handler，但前端全仓**无调用入口**（grep `miniprogram/` 零命中），用户确认进度实际全靠 `order-timer` 超时 15min 自动确认（`processMilestoneConfirm`）。改 milestone 节点（如 T-18.1 三改二）时**勿假设前端有确认按钮**；`finish_apply` 门槛现行只看 `milestone.current`，不看 `confirmed`。
