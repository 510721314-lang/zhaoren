《TRAE 环境开发微信小程序综合评审框架》

一、评审总原则（TRAE 场景先说清）

TRAE 的价值是“意图→代码”提速，但 AI 生成代码默认存在三类原罪，评审时必须人工兜底：
• API 版本幻觉：用了已废弃/旧基础库接口

• 上下文漂移：改 A 页面顺手改坏 B 页面逻辑

• 合规盲区：把虚拟支付、隐私、UGC 审核写成“能跑就行”

结论：AI 出代码 ≠ 可交付，评审 = 机器检查 + 人工决策 + 真机验收。

二、综合评审维度与判分标准（满分 100）

1. 架构与工程化（18 分）

评审点：
• 目录分层：pages / components / services / utils / store 是否清晰

- 是否页面直连接口（应走 request 封装层）
• 状态管理：全局登录态、用户信息、订单态是否统一（非每页各存一份）

• TS 覆盖：类型定义、接口返回结构是否有类型

• TRAE 上下文治理：前后端分会话、关键改动有 git 提交、有 .rules 约束平台合规

• 环境隔离：dev / test / prod 配置分离，无硬编码 AppSecret、Token

扣分项：
• 页面里直接写 wx.request 裸调用 → 扣 3

• 密钥写前端 → 扣 5 且阻断上线

• 无 git 版本锚点 → 扣 2

2. 功能完整性与主链路（20 分）

• 核心链路（如：浏览→下单/预约→支付/确认→结果）全程可跑通

• 异常分支：未登录、超时、库存空、取消、重复提交、网络断开

• 所有按钮有响应，无“测试”“aaa”占位

• 账号体系有体验账号可测全部功能

TRAE 特有坑：
• AI 生成数据格式错（选项数组合并、引号混用）→ 必须跑数据校验脚本 

3. 性能体验（18 分）

按微信官方评分口径：
• 主包 ≤2MB（建议 ≤1.5MB），分包加载

• setData 只传渲染用字段，不传大对象

• 长列表用 recycle-view 虚拟滚动

• 图片 WebP+CDN+懒加载，单图 ≤300KB

• WXML 层级 ≤10 层

• 首屏：骨架屏 + 接口预取，目标首屏 <1.5s

• 定时器/监听在 onUnload 回收

• 真机反复进出页面 10 次，内存不涨

4. 稳定性与容错（12 分）

- 全局 App.onError / onUnhandledRejection 上报
• 请求超时（15s）+ 重试（≤3 次）+ 降级数据

• 白屏/空数据/接口 500 有兜底页

• 云函数幂等（防重复打卡/重复支付）

- 弱网（地铁/电梯）不崩

5. 安全（15 分）

• 全站 HTTPS，域名白名单配置

• 敏感数据不落本地：手机号、身份证脱敏

• Token 有刷新机制，鉴权失败跳登录

• 后端校验一切（价格、库存、权限），不信任客户端

• 无硬编码密钥，MCP/三方服务最小权限

• UGC 文本/图片接 msgSecCheck / imgSecCheck

6. 隐私与平台合规（10 分，红线项）

• 隐私协议填写：每个接口写清“哪个页面、什么目的” 

- 权限申请：位置/相册/手机号先说明再授权，拒绝后不反复弹
• 无诱导分享、无虚拟支付（个人主体禁交易）

• 有账号注销、退出登录

• 类目资质齐全（医疗/宠物/陪玩类尤其注意服务类目）

合规项一票否决：隐私描述乱填、虚拟支付、UGC 无审核。

7. 多端真机验收（5 分）

• iOS 真机 + Android 真机各跑主链路

• 相机/定位/蓝牙/支付必须真机（模拟器不可信）

• 鸿蒙/PC 如覆盖则加分

8. AI 协作可维护性（2 分）

- 有 PRD/技术文档（TRAE /plan 产出可追溯）
• 关键会话 Session ID、版本号可回溯

• 每次 AI 改动有 commit message 说明“改了什么、为何改”

三、TRAE 开发专属“AI 代码体检”清单

检查项 命令/动作

废弃 API 扫描 全局搜 getUserInfo 等旧接口，对比当前基础库

未定义组件 编译报错 + 查 json 引用

setData 大对象 性能面板看传输体积

内存泄漏 真机重复进出页面

数据格式校验 对列表/选项/富文本跑 schema 校验

配置漏填 云环境 ID、AppID、域名白名单、隐私接口

上下文污染 新功能新开对话，旧对话只修 bug

四、上线前闭环动作（SOP）

1. TRAE 跑“全项目巡检”一次（修回归）
2. git 打 tag（如 v1.0.0-review）
3. 微信开发者工具：体验分评分（目标 ≥90）
4. 体验版发非开发者微信号全流程走查
5. 提审材料：隐私协议、测试账号、类目资质
6. 灰度 5%→全量，留回滚

五、综合评级参考

• ≥85 分：可提审，商业级交付

• 70–84：可内测，需补性能/容错

- <70：返工，AI 代码未受控

六、可附带的评审输出物（建议你交付时带这些）

• 评审打分表（按上面 8 维）

• 问题清单（P0 阻断 / P1 高优 / P2 体验）

- 真机测试录屏（iOS+Android）
• 隐私接口对照表

• TRAE 会话与版本溯源说明

补两个核查点：全局错误上报是否在别处实现、是否存在裸 wx.request 调用。
