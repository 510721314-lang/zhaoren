## 6. 经验教训（最高频陷阱，完整版见 project_memory）
- ★【最高风险·发布时序】任何新增服务端 fail-closed 前置门（新错误码/新资料校验/新鉴权），必须先发（重传）客户端、再部署云函数；旧客户端被拒是预期 fail-closed 行为不是 bug——真机回归前先确认开发版已含对应前端（当前最新 1.6.6）。
- 【挂起 action 勿回切】前端已切 start_apply（#69），旧 start_service 与 start_photo 服务端保留共存、无前端入口是有意设计（action_lifecycle.js L149「待前端切换后收口」），勿当缺陷回开。
- 【状态相关卡片】放在某状态 wx:if 块内的卡片会随状态推进消失——跨状态恒显的凭证卡放顶层（4233660 实证）。
- 【隐私接口】getLocation/chooseMedia 需 __usePrivacyCheck__ + 后台隐私声明齐备，否则真机静默失败；先查 mp-privacy-release 技能再怀疑代码。
- 【IDE 白屏定性】真机正常=代码无责；模拟器可能渲染陈旧编译产物；终解=结束全部微信开发者工具进程后重开 c:\zhaoren，勿盲改代码。
- 【备份判活】L6 日志长时静默 ≠ 卡死（20 函数含 node_modules 465MB 约 20 分钟），看 functions_code\<fn>\ 文件数增长；PS5.1 Add-Content -Encoding ASCII 会把中文写字面 ?（写中文用 .NET UTF8 无 BOM，本次已踩已修）；云端下载件 CRLF 可能变 LF，比对先归一化行尾。
- 【CloudBase】where().get() 取 r.data[0]、doc().get() 直接 r.data；aggregate 必须链式；命令行内联中文变 ?，中文载荷写 UTF-8 文件再发。
- 【前端】showModal 的 confirmText/cancelText ≤4 字符否则真机不弹窗；WXSS 禁 BOM；需服务端生效的参数必须落库，Storage 仅离线兜底。
- 【Bug 纪律】一次只验证一个假设；连续两次未解决立即停手要报错原文/Console/复现步骤；禁扫射、禁 try/catch 吞异常、禁 setTimeout 掩盖时序。
