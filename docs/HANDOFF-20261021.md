## §6 经验教训【清点项】

> 本表为**高频必守子集**；`HANDOFF-20261019.md` §6 的 **E-6.1~E-6.33 仍全量有效**，冲突时以更严格者为准。

- **E-6.1 三重假阳性**：门禁绿+部署 success+SHA 一致都不证明云端可加载。实证：`user-login` 拆分后 `getCachedEnv` 不在作用域 → `submit_realname` 恒 `login_server_error`，A/B 却判"等价"（基线同缺该符号，两侧同错）。
- **E-6.2 A/B 只证"和基线一样"**：不证"是对的"；每条新链须有独立契约测试（本轮 +7 +4 例）。
- **E-6.3 服务端拒绝码必须配出路**：前端缓存陈旧会绕过本地守卫；每个码给"下一步去哪"，禁只弹 toast（接单链 8 个码已全配）。
- **E-6.4 编码三连环**：BOM 丢失 / BOM-less JSON 按 GB2312 解码吞引号 / native stdout 乱码；写端带 BOM + 读端显式 UTF8 + native 落盘后读（§25-J1/J2/J3/J6）。
- **E-6.5 TCB `_id` 过滤**：等值静默不命中；命中 0 先怀疑过滤形态（§24-I1）。
- **E-6.6 统计用 count**：`limit` 会把 1541 读成「≥500」。
- **E-6.7 软删优先**：清理默认打标 `is_deleted=true`、逐单串行、写后复测「打标数=预期 ∧ 未打标=0」；打标≠隐藏。
- **E-6.8 先查再做**：`auto_approve_partner` 线上为 `true` 但 `config_history` 无记录（P1-7）；配置现值必须只读实查，禁凭默认值推断。
- **E-6.9 可读化标识量化熵**（§26-K1）：64 bit→33 bit 不是"差不多"；改格式同步读侧双形态。
- **E-6.10 门禁 fail-open**：仅遍历手工清单的校验会漏登记即静默通过；新脚本双挂载。
- **E-6.11 网关间歇 400/504**：响应体可能为空；必须带重试，诊断打印 HTTP 状态与体。
- **E-6.12 变量名撞名**：包装器参数与被包装作用域变量同名（`$Body`/`$body`）→ 空请求体，症状伪装"网关间歇故障"；用「同点直连 vs 包装器」二分定性。
- **E-6.13 专家审核双维度**：事实核验（A）+ 完整性/偏离（B）不可省；B 专抓漏项与过度声称；**1/1 低置信不修，2/2 确认才立项**。
- **E-6.14 WXSS 注释陷阱**：禁 `*` 紧跟 `/`（glob 提前闭合 → 预览 `Unexpected '/'`）；只查 `.wxss`。
- **E-6.15 隐私接口**：`getLocation`/`chooseMedia` 需 `__usePrivacyCheck__` + 后台隐私声明齐备，否则真机静默失败；`requiredPrivateInfos` 仅限定位类 8 项。
- **E-6.16 dormant bug 警戒**：首次使用相邻/冷门页面暴露的既有 bug，不归咎本次改动，但须立即修复并登记（实例如 admin-web Audit 页）。
- **E-6.17 Bug 纪律**：一次一假设；连续两次未解决立即停手并上报错误原文，禁蛮力重试。
- **E-6.18 UI 文案约束**：toast 中文提示 ≤14 字；`showModal` 的 `confirmText`/`cancelText` ≤4 字符，否则真机不弹窗；「确认→云调用」须页级互斥包装，前端锁不替代服务端幂等。
