# 微信小程序 · AI 协作防回退规则

核心目标：杜绝"改一个 bug，坏三个已调好的功能"。

## 0. 开工前必读（不可跳过）
动手改代码前必须先读：
1. 本文件
2. docs/FUNCTION-REGISTRY.md —— 已验证功能清单与人工验收步骤
3. docs/CHANGELOG.md —— 近期变更与回归结论
未读取就改代码视为违规。文件不存在时先提醒我创建。

## 1. 第一原则：最小改动
- 除非我明确要求，禁止对已能正常运行的代码做：重构、性能优化、统一风格、格式化、重命名、调整目录、更换写法、补注释、删除"看起来没用"的代码。
- 禁止整文件重写，禁止"重新生成整个页面"。只做增量修改。
- 单次改动默认上限：3 个文件、30 行。超出先停下来问我。
- 我让你改 A，不能顺手改 B。禁止"顺便优化""顺手修一下"。
- 看不懂某段代码用途时先问，禁止猜测后删除或改写。
- 改 WXSS 时只改目标选择器，禁止重写整个样式块、禁止改全局 app.wxss 除非点名。

## 2. 已验证代码神圣不可侵犯
- 带 // @VERIFIED 标记的函数/组件/文件表示已通过真机验证：
  - 禁止修改其内部逻辑，除非本次需求中点名要求；
  - 确需修改时，先说明"为什么必须改" + 给出向后兼容方案（旧调用方、旧字段名仍可用），等我书面批准。
- 我告诉你某功能调通后，主动提醒我加标记：// @VERIFIED 日期 已真机验证：xxx

## 3. 先说后做（我批准前不得写入文件）
动手前只输出方案，必须包含：
1. 根因定位：精确到 文件路径:行号，说明为什么错。禁止"大概是""可能是"的猜测式修改。
2. 改动清单：每个文件改哪一处，各一句话。
3. 影响面评估：对照 FUNCTION-REGISTRY 逐条比对，列出可能被波及的既有功能。
4. 风险等级：高/中/低 + 判断依据。
5. 触发以下任一条件必须停下来问我：
   - 涉及 app.json / app.js / app.wxss / project.config.json / sitemap.json / ext.json
   - 涉及公共组件、utils/、request 封装、登录态 / token 逻辑、全局状态
   - 涉及接口字段、云函数、数据库集合、缓存 key
   - 涉及基础库版本、插件、分包结构、渲染引擎、npm 依赖
   - 涉及登录、授权、支付、订阅消息、上传下载、定位等能力链路

## 4. 小程序高危改动区（碰之前必须说清后果）
| 高危项 | AI 最常犯的错误 | 强制要求 |
|---|---|---|
| app.json | 新增页面忘记注册、改动 tabBar 顺序、误删已注册路径 | 新增页面必须同步注册；禁止改动已有 tabBar 项与页面路径 |
| project.config.json | 误改 appid、miniprogramRoot、npm 打包配置 | 禁止擅自改动；确需改必须说明并单独提交 |
| project.private.config.json | 覆盖个人编译条件、勾掉"不校验合法域名" | 一律禁止修改 |
| 基础库版本 | 擅自调高导致低版本用户白屏 | 禁止改动，除非我要求 |
| 渲染引擎 | 误开 Skyline，导致 WXSS 大面积失效 | 禁止改动 renderer / rendererOptions |
| setData | 整对象覆盖、单次数据量过大、后台页调用 | 只传变化字段或用路径写法；长列表禁止整体替换 |
| 组件 properties / data | 字段改名后 WXML 引用失效 | 改名前列全部引用点，经我确认后再改 |
| 样式隔离 | 组件样式不生效就改全局 | 先说明 styleIsolation 方案，禁止直接搬进 app.wxss |
| 云函数 | 改了本地代码不部署就说"已修复" | 必须提示我"需右键上传并部署" |
| npm 包 | 装完没构建就说能用 | 必须提示我"需执行构建 npm" |

## 5. 小程序专项红线
- 页面栈：navigateTo 最多 10 层；switchTab 不能带参数；redirectTo 会销毁当前页。改动跳转逻辑必须列出受影响的返回路径。
- 生命周期：onLoad 只执行一次、onShow 每次进入都执行、tabBar 页不会触发 onUnload。改数据初始化位置时，必须说明为什么放在对应生命周期。
- 登录时序：wx.login → 自定义登录态 → 业务请求 的顺序不得打乱；禁止在 app.js 内加"顺手"的并发改造。
- 隐私协议：涉及 getUserProfile / getPhoneNumber / 相册 / 定位等，必须确认已在 app.json 的 __usePrivacyCheck__ 与小程序后台配置，否则接口静默失败。
- 合法域名：新增接口域名必须提醒我去后台配置 request 合法域名，否则真机必失败。
- 体积限制：主包 2MB、单分包 2MB、总包 20MB。新增依赖必须评估体积影响。
- 能力链路：登录、支付、授权、订阅消息、上传下载、蓝牙、定位——任何相关改动一律列为回归清单第 1 条，并标注"必须真机验证"。
- UI 改动：滚动、键盘弹起、安全区、字体、图片、rpx 适配——一律标注"需 iOS 与 Android 真机各验一遍"。

## 6. 改完必交回归验证清单（缺此项 = 任务未完成）
任何改动后必须输出：
1. 变更清单：文件 + 改了什么 + 为什么改。
2. 回归验证清单（表格）：序号｜需回归的既有功能｜验证步骤（开发者工具/真机）｜预期结果｜谁验。
3. 区分两类验证：你可在开发者工具自证的（语法、编译、Console 无报错、Network 请求字段）你自己过一遍并说明结果；必须由我人工/真机验证的明确列出，不要含糊带过。
4. 涉及云函数、npm 构建、后台配置时，在清单里单列"需我手动操作"项。
5. 禁止以"已完成""应该没问题""现在可以了"收尾而不给验证步骤。

## 7. Bug 修复纪律
- 一次只验证一个假设，禁止把多套方案同时塞进去的"扫射式修改"。
- 连续两次尝试未解决，立即停下：说明现状 + 已排除的可能 + 需要我提供什么（报错原文、开发者工具 Console 日志、复现步骤、真机表现截图）。禁止继续盲改。
- 治本不治标，禁止以下"假修复"：用 try/catch 吞掉异常；用 setTimeout / 加大延时掩盖时序问题；注释掉代码、加 return 跳过逻辑；把 wx:if 改成 hidden 绕过渲染报错；反复 setData 空对象"试试看"。
- 需要报错信息或真机表现时先向我要，禁止凭想象编造。

## 10. 大型机械重构与 A/B 门禁纪律（2026-10-14 实证新增）
- A/B「0 差异」≠ 行为正确。A/B 只比较**单次调用返回值**，以下三类盲区必须各补一道独立测试：
  1. **跨调用有状态行为**（进程内缓存/锁/计数器/单例）：同一模块实例连调两次，断言第二次的副作用计数（如 DB 查询次数）下降或为 0——单调用断言永远发现不了"缓存因 TTL=NaN 永不命中"这类问题。
  2. **静默退化**（ctx 漏注入的常量/参数变 undefined，不抛错只改变行为）：静态核对「index.js 的 ctx 提供键 ⊇ handler 解构且体内真实使用的键」；机械扫描必须排除四类误报——require 路径字符串（如 `'./openid'`）、对象键名（`{openid: x}`）、解构行自身、函数体内同名局部声明。
  3. **成功路径从未走通**（A/B 两侧同抛错也判"等价"，会互相背书）：每个核心写动作至少一条用例真正穿透到落库，断言返回值 + writes 副作用（多表写入/状态 CAS/审计/通知），不能只覆盖错误码分支。
- `KNOWN_EVOLUTION` 白名单是「跳过该例比较」而非「提供保护」：每登记一例，必须另配一条独立行为断言，否则该路径永久失去回归守护。
- `_orig_baseline.js` 冻结入库常驻（A/B 锚点，**测完不删**）；修复基线时代既有 bug 时**不刷新基线**（差异走 KNOWN_EVOLUTION 留证），修复提交必须与重构提交分离。
- 多文件/多提交机械重构收尾，默认追加一次「执行者之外」的独立审查（双视角独立取证、2/2 确认才立项修复，1/1 低置信只登记）；审查只报线上故障级（注入完整性、缓存/锁单例归属、块作用域越界、鉴权顺序、事务副作用一致性），禁止凑风格问题。
- 重构中发现的既有 bug 只登记不手修；修复须单独授权、独立提交、独立回归（接单/支付等能力链路必须真机验证）。

## 12. 上线核验与历史保全纪律（2026-10-15 实证新增）
- **顺序铁律**：云函数部署前置门禁要求「该函数已 commit」（否则 exit 6）⇒ **先 commit 再 deploy**；改动云函数必须重新部署、改动前端必须重新 preview/upload，且**部署/重传后必须 download 比对 SHA256 或看日志回执**，禁止用「脚本报了成功」代替核验。
- **禁止用包体字节数变化判断前端改动是否生效**：`minified` / `minifyWXML` 会剥离注释与缩进，注释类改动、同一元素换位置**不改变产物字节**（2026-10-15「履约凭证卡上移」即为此例）；核验手段应为 `cli close` 强制新 IDE 会话重编译 + 源码回读 + 编译 EXIT 码，而非体积数字。
- **提交信息直传中文原文**（禁止用 `\uXXXX` 转义拼串），提交后必须读 `git log -1` 回执校验；若已产生乱码且**尚未推送**，经我批准可**一次性重写该提交说明**（`reset --soft` 重放或 amend HEAD），并同步修正文档中引用的 hash；**已推送后禁止重写历史**。
- **状态机 SSOT 与 handler 层白名单必须同步**：改任一侧就要同步规则表 `no.x` 的 `from`、3 份副本（跑 `cloudfunctions/_shared/sync-*.ps1`）与对应测试断言（含反向断言），否则口径漂移（2026-10-15 规则 no.16 收窄 S5/S8 即为此例）。
- **执行环境兜底**：ToolHost 不可用时改用 Exec(code mode)，并**显式补 PATH + 全路径**调用（`C:\Program Files\nodejs\npm.cmd`、`C:\Program Files\Git\cmd\git.exe`）——该通道 PATH 精简，`git`/`node` 都不在 PATH 内。
- **推送/联网失败先验代理**：若 `github.com:443` 不通而常规域名（baidu / api.weixin.qq.com）通 = **定向阻断**（非断网、非 DNS、非仓库问题）；本机代理在 `127.0.0.1:7890` 监听、但系统代理 `ProxyEnable=0` 时，**不得改 git config / 系统设置**，仅在该次命令注入 `$env:HTTPS_PROXY=http://127.0.0.1:7890` 后重试，并用 `git ls-remote origin -h refs/heads/master` **核实远端 hash == 本地 HEAD**（禁止只看 push 回显）。PowerShell 5 下 git push 的进度走 stderr，会被标红/包成 `NativeCommandError`——**以 exit code=0 + ls-remote hash 一致为准**，勿把标红噪音误判为推送失败（2026-10-15 实证）。

## 13. 小程序前端写操作防连点与提示时序纪律（2026-10-15 实证新增）
- **真机实证（订单详情连点跳出原逻辑）**：凡「`wx.showModal` 确认 → 云调用写操作」的 handler，**禁止裸调 `wx.showModal`**。弹窗渲染存在空窗，快速连点会堆叠两个 modal：首请求 CAS 改状态 + fetchData 换掉按钮后，第二个 modal 的确认对新状态二次请求，服务端以 `oa_*_status`/`oa_status_conflict` 拒绝，前端再把含裸状态码的 `r.msg` 直接弹给用户。注意 `wx.showLoading({mask:true})` 只遮住 loading 期间；modal 弹起到点确认、以及确认后到 loading 出现前均无遮罩。
- **统一走页级互斥包装**（参照 `pages-v2/order-detail/order-detail.js` 的 `_modal`，commit 6654403）：互斥标志挂页面实例（**不入 data、不 setData**），在**弹窗前入口**即拦；放锁必须覆盖三条路径——点取消、弹窗 fail、业务 Promise 链结算（`.then(release, release)` 兜底，success 回调必须 `return` 其 Promise 链）；成功后的 fetchData 要 return 进同一条链，保证放锁时按钮已按新状态重渲染，杜绝「放锁瞬间旧按钮仍在」。
- **「取消键也是业务动作」的弹窗必须显式放行**：同意/拒绝共用一个 modal（如加时确认弹窗取消键=「拒绝加时」）时用 `cancelIsAction` 类开关让回调照常执行，禁止一律把 `!res.confirm` 当放弃处理。
- **状态冲突错误码不直出 `r.msg`**：码名匹配 `/_status$|status_conflict/` 时静默 fetchData + 固定友好文案（如「订单状态已更新, 请刷新后重试」）；权限/冷却/次数/资金/文本安全等业务错误**仍走原文案**，禁止一刀切吞掉所有 `!r.ok`。
- **成功反馈时序**：写操作成功后 loading 保持到 fetchData 刷新完成再弹成功 toast（堵慢网刷新空窗的重复点）；fetchData 类刷新函数须返回 Promise（既有调用方不接返回值，天然向后兼容）。
- **`wx.navigateTo` 的 success 回调里禁止 toast**（跨页提示在目标页多余）；返回原页所需的刷新交给 onShow 兜底，不靠跳转前 toast 交代状态。
- **修复切口**：只做「加包装器 + 逐 handler 替换调用」，不重写既有回调体；带 `// @VERIFIED` 且本次未点名的 handler 不动，未覆盖的同构 handler 在 FUNCTION-REGISTRY 单列残留项由我决定是否扩面，禁止借修 bug 顺手扩面。
- **前端锁不替代服务端幂等**：互斥锁只改善交互体验，资金/状态推进仍以服务端 CAS + 写操作不重试为准（本项目已具备）；禁止以「前端已加锁」为由放松任何服务端状态/权限校验。

## 14. 输入校验口径变更与提示文案纪律（2026-10-16 实证新增）
- **`wx.showToast` 文案长度红线**：中文提示控制在 **≤14 字左右**（icon 非 none 时更短，最多两行且第二行易被裁断）。2026-10-16 实证「请填写正确的手机号，或带区号的座机号（如 028-88888888）」24 字在真机第二行被截断。**新增/修改任何 toast 文案先数字数**；要举例/给细则的长说明改用 `wx.showModal` 或放表单内联提示，禁止塞进 toast。
- **收窄/取消一种输入格式（如座机、某类证件）必须前后端同改、一处不漏**，以 #77 为标准切口：
  1. 前端纯校验函数正则 + 错误文案（缩短）；
  2. wxml `<input>` 的 `type`（如 `type="number"` 物理拦截）、`maxlength`、`placeholder` 三处同步；
  3. 前端单测：旧格式「放行」用例**反转为拒绝**，新格式边界（少一位/多一位）补齐；
  4. 服务端同口径校验 + ctx 注入键名 + 错误文案；错误码名保持不变（只收紧判定），避免前端/文档断链；
  5. 按 §10 补**服务端独立反向断言**（旧格式穿透到该校验必须被拒），不能只靠前端口径与 A/B 等价。
- **展示层旧格式分支刻意保留**：取消座机「输入」后，`maskContact` 等脱敏/展示函数里的座机分支**不能删**——历史已入库的旧格式数据仍要正常展示。判定原则：**写入校验可收紧，读取/展示必须向后兼容存量数据**；删除任何旧格式分支前先确认无存量数据。
- **前端与云函数分两个 commit**（前端、服务端分离便于单点回滚）；服务端 commit 必须按 §12 先 commit 再部署 + download SHA256 核验；前端随新版本上传。两者都上线前，存在「服务端已拒、旧前端仍引导填写」的短暂窗口，属预期收紧方向，CHANGELOG 要写明。

## 15. 关键配置权威来源与 GUI 自动化纪律（2026-10-16 实证新增）
- **关键 ID/配置一律以仓库文件实测为准，不信任交接摘要/记忆中的值**：AppID 权威 = `project.config.json`（实证交接摘要误记 `...204f5`，实际 `...234f5`）；云环境 ID 权威 = `cloudbaserc.json` / `miniprogram/envList.js`；地图 key 权威 = `miniprogram/config/index.js`。跨会话续作先用命令核实再使用，发现文档值与配置不符以配置为准并订正文档。
- **第三方 key 白名单是「多产品独立开关」**：腾讯位置服务 key 需同时开通 WebServiceAPI **并**单独勾选「微信小程序」授权、填入小程序 AppID 白名单（实证该开关原未勾选，与 WebServiceAPI 互不为前提）；改后重开编辑框核验已持久化，并用该 key 实发一次接口请求（如逆地理返回 `status=0`）作为功能佐证。
- **computer-use 驱动微信开发者工具/浏览器时**：
  1. 优先用 UI 树返回的 **element_id 精准点击**，坐标点击在深色高密度工具栏上连续误触（实证误开「编译模式」下拉与「添加编译模式」对话框）；一旦误开「添加编译模式」类对话框只点取消，**禁止点确定**以免写 `project.private.config.json`（§4 红线）。
  2. **快捷键焦点可能落在小程序模拟器而非 IDE**（Ctrl+B 实证触发小程序「查找场景值」）；无 element_id 可点时让用户用鼠标点工具栏，不代按快捷键。
  3. computer-use 前先用「关闭查找栏/Esc + 确认焦点窗口」清理现场；每次关键点击后截图取证再进下一步。
  4. Exec 代码通道的成功返回值在部分环境不回显（throw/console 也不可用），直接以 run_mcp 单步调用 computer-use 工具为准。
- **推送网络状态会动态切换**：Clash 7890 可能临时未监听、github 直连也可能间歇恢复/再被阻断。推送前先 `Test-NetConnection 127.0.0.1 -Port 7890` + 常规域名对照（§12），哪通用哪、**仅当次注入**；直连可用时 `git -c http.proxy= -c https.proxy=` 当次清空，任何情况下不改 git config/系统代理，一律以 exit=0 + `ls-remote` hash == HEAD 为成功判据（stderr 标红的进度文本不算失败）。
- **微信开发者工具 Console 执行纪律（2026-10-16 实证新增）**：①**粘贴的多行 JS 会被按行逐条执行**，多行对象字面量被拆断报 `Unexpected token '}'` → 多步验证一律拆成**各自单行**命令（实证：把"注入草稿/调用 restoreDraft/打印结果"拆成三条单行才跑通）；②模拟器停在预览/白板视图时 `getCurrentPages()` 返回**空数组**（需先「编译」或从首页进入页面，页面栈为 `pages-v2/index/index` 时方可取页面实例）；③在无某字段的页面上打印该字段（如 index 页的 `draftCount`）得 `undefined` 属正常，不可当异常；④可用 `页面实例.方法名(...)` 直接调用页面方法做受控验证（比手点更硬，且绕开入口/角标依赖）。

## 16. 云函数批量部署 · 提交信息乱码判定 · 测试基建口径（2026-10-17 实证新增）
- **CLI 多函数部署必须逐个、download 核验必须各自独立目录**：`cli cloud functions deploy --names a,b`（逗号分隔）会报 `Error: cloudfunction path not found` 且 **DEPLOY_EXIT 仍为 0**（成功回执误导）——必须**逐函数单独** `--names <fn>` 执行并逐条核对 success；多函数 download 核验须**各自独立 `-p` 目录**（共用同一目录时 `index.js` 互相覆盖，无法逐函数 SHA256 比对）。
- **提交信息「乱码」先验显示编码，再判是否重写**：PowerShell 5 控制台默认 GBK，`git log` 输出的 UTF-8 中文会被显示成乱码（实证 `璁㈠崟`），但**存储可能完全正确**。复核手段：`$OutputEncoding = [Console]::OutputEncoding = [System.Text.Encoding]::UTF8` 后重看 `git log -1`；**只有确认存储真乱码且尚未推送才可重写**，禁止仅凭控制台乱码就误判并重写提交历史（与 §12「已推送后禁止重写历史」配套）。`git commit -F <UTF-8 无 BOM 文件>` 存中文正常，回执一律以 UTF-8 console 复核为准。
- **`_mock_sdk` 等值匹配：fixture 须显式带 `is_deleted:false`**：`where().get()` 的等值比较是 `dv === qv`，fixture 缺该字段时 `undefined !== false` 静默不匹配 → 查回空数组、用例误 fail。凡断言「按 `{user_openid, is_deleted:false}` 查询命中」的 fixture **必须显式带 `is_deleted:false`**（实证 `my_orders` 两例首跑 fail 即此因）。
- **node:test 汇总行抓取口径**：新版 Node 的汇总行为 `ℹ tests N / ℹ pass N / ℹ fail N`（**非** `# ` 前缀），脚本抓取改用 `Pattern "tests |pass |fail "`，勿沿用 `Select-String -Pattern "^# "`（实证抓空）。
