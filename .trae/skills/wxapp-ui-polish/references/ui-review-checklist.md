# 微信小程序 UI 走查清单

对每一条打 ✅ / ❌，❌ 项必须给出"文件:行号 + 修复建议"，严重度分高/中/低。

## 一、视觉一致性（最影响"土不土"）
- [ ] 全项目是否只有一套色板？硬编码色值是否已全部替换为 CSS 变量
- [ ] 主色使用面积是否克制（≤ 视觉面积的 10%，其余交给中性色）
- [ ] 同一种元素（卡片 / 按钮 / Tag / 列表行）在不同页面样式是否一致
- [ ] 圆角是否收敛到 3 档以内，没有出现 5rpx / 7rpx / 13rpx 这类随机值
- [ ] 阴影方向、模糊度是否统一，没有"有的卡片有阴影有的没有"
- [ ] 图标是否为同一套（同为线性或同为填充），尺寸是否统一
- [ ] 分割线是否统一（颜色、粗细、是否与边缘齐平）

## 二、排版与留白
- [ ] 卡片内 padding ≥ 24rpx，元素之间不再"贴脸"
- [ ] 正文行高 ≥ 字号的 1.5 倍
- [ ] 字号层级不超过 4 级，且每级有明确用途
- [ ] 文本对齐方式统一（正文左对齐，数值可右对齐）
- [ ] 一屏是否只有一个视觉重点，没有"到处都在抢注意力"
- [ ] 长文本是否有截断策略（单行 ellipsis / 多行 -webkit-line-clamp）

## 三、交互反馈（最容易漏）
- [ ] 所有可点击元素都有 `:active` 态（缩放 / 变浅 / 阴影变化任一）
- [ ] 按钮、表单都有 `disabled` 态，且视觉上明显不可用
- [ ] 加载中有骨架屏或 loading，**没有白屏干等**
- [ ] 网络异常 / 超时 / 无网有明确提示和重试入口
- [ ] 操作成功 / 失败都有 toast 或结果页反馈，且文案是"人话"
- [ ] 危险操作（删除、清空）有二次确认
- [ ] 下拉刷新、上拉加载更多是否正常（列表页）

## 四、状态完整性
- [ ] 空数据有空态插画 + 引导文案，而不是一片空白
- [ ] 图片加载失败有占位图 / 默认图
- [ ] 未登录 / 鉴权失败 / 账号切换有对应状态页
- [ ] 数据极值（超长昵称、超大金额、0 条记录）不破版

## 五、适配与规范
- [ ] 单位统一 rpx，没有混用 px 导致小屏溢出
- [ ] 底部操作区适配 `env(safe-area-inset-bottom)`
- [ ] 右上角官方胶囊区没有被可交互元素遮挡
- [ ] 全面屏 / 小屏（iPhone SE 宽度）不出现横向滚动
- [ ] tabBar icon 为 81×81px，数量 2–5 个，选中态与未选中态区分明确
- [ ] 可点击区域 ≥ 88rpx × 88rpx
- [ ] 本地图片未用作 `background-image`（小程序限制），已改为 base64 或网络图

## 六、性能与体积
- [ ] 主包 ≤ 2MB，超出部分已拆分包
- [ ] 图片已压缩，优先 WebP，列表图有懒加载
- [ ] 自定义组件嵌套层级不过深（影响 setData 通信开销）
- [ ] 没有为装饰性效果引入重型动画库

## 七、文案
- [ ] 无错别字，无中英文标点混用
- [ ] 按钮文案是动词短语（"提交订单"而非"确定"）
- [ ] 未使用内部术语 / 技术黑话
- [ ] 提示文案说清"发生了什么 + 下一步怎么办"

## 八、可选加分项
- [ ] 深色模式适配
- [ ] 适老化（字号放大、对比度提升）
- [ ] 分享卡片封面与标题配置
- [ ] 首屏渲染时间优化（LCP）
